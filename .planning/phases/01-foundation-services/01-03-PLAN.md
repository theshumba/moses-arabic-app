Create `src/services/StorageService.js` — the ONLY module that touches localStorage directly.

**API:**

```js
const STORAGE_PREFIX = 'moses-arabic-'
const DEBOUNCE_MS = 2000  // 2 second debounce for writes

export const StorageService = {
  // Core CRUD
  get(key) {},           // Returns parsed JSON or null. Key auto-prefixed.
  set(key, value) {},    // Debounced JSON.stringify + localStorage.setItem. Key auto-prefixed.
  setImmediate(key, value) {}, // Non-debounced write (for critical saves like session end)
  remove(key) {},        // localStorage.removeItem. Key auto-prefixed.

  // Bulk operations
  exportAll() {},        // Returns JSON string of all moses-arabic-* keys
  importAll(jsonString) {}, // Validates JSON, clears existing, imports all keys
  clear() {},            // Removes all moses-arabic-* keys

  // Lifecycle
  flushAll() {},         // Forces all pending debounced writes immediately
  getQuotaUsage() {},    // Returns { used: bytes, limit: '5MB', percent: number }
}
```

**Implementation details:**

1. **Debounced writes:** Use a pending writes Map. `set(key, value)` stores in pending map and (re)starts a setTimeout. When timeout fires, write all pending to localStorage. `flushAll()` writes all pending immediately and clears timers.

2. **Key prefixing:** All keys prefixed with `moses-arabic-`. The get/set/remove methods add the prefix automatically. Export/import strips/adds prefix.

3. **QuotaExceededError handling:** Wrap localStorage.setItem in try/catch. On QuotaExceededError, log warning to console, return false from set. The caller can handle gracefully.

4. **exportAll():** Iterate localStorage keys, filter by prefix, build object, return JSON.stringify. Include a `_meta` key with version and timestamp:
```js
{ _meta: { version: 1, exportedAt: new Date().toISOString() }, ...data }
```

5. **importAll(jsonString):** Parse JSON, validate `_meta.version`, clear existing data, write all keys. Throw on invalid JSON or missing version.

6. **getQuotaUsage():** Estimate by JSON.stringify-ing all prefixed keys. Return bytes used.

**IMPORTANT:**
- NO React imports. This is a plain JS module.
- Timer IDs stored in a module-level Map for cleanup.
- `flushAll()` must be callable from window.beforeunload to prevent data loss.

Create `src/services/SrsService.js` — pure functions implementing SM-2 spaced repetition.

**API:**

```js
export const SrsService = {
  // Card progress lifecycle
  createCardProgress(cardId) {},
  reviewCard(progress, rating) {},

  // Queue building
  getDueCards(allProgress, cardIds, now) {},
  getNewCards(allProgress, cardIds, limit) {},
  buildStudyQueue(allProgress, cardIds, options) {},

  // Again management
  shouldReshow(cardId, againCounts) {},
  getInterleavingDistance(againCount) {},

  // Helpers
  isCardMastered(progress) {},
  isCardDue(progress, now) {},
}
```

**createCardProgress(cardId):**
Returns:
```js
{
  cardId,
  interval: 0,          // days until next review (0 = new/learning)
  repetition: 0,        // consecutive correct reviews
  easeFactor: 2.5,      // SM-2 ease factor (min 1.3)
  nextReview: null,      // ISO date string or null (new card)
  lapses: 0,            // times forgotten (Again count)
  lastRating: null,      // 1-4
  totalReviews: 0,
  step: 0,              // learning step index (0=new, 1=1min, 2=10min, 3=graduated)
}
```

**reviewCard(progress, rating):**
Returns NEW progress object (immutable — never mutate input).

Rating logic:
- **Again (1):**
  - Reset step to 1 (1-min learning step)
  - interval = 0 (intraday)
  - repetition = 0
  - lapses += 1
  - EF -= 0.2 (min 1.3)
  - nextReview = now + 1 minute

- **Hard (2):**
  - If in learning (step < 3): stay at current step, nextReview = now + current step interval
  - If graduated (step >= 3): interval = Math.max(1, interval * 1.2), EF -= 0.15 (min 1.3)
  - repetition += 1
  - nextReview = now + interval days

- **Good (3):**
  - If in learning (step < 3): advance step. Step 1->2 (10min), step 2->3 (graduate, interval=1day)
  - If graduated: interval = Math.max(1, Math.round(interval * EF))
  - **EF RECOVERY (CRITICAL — Pitfall #1):** If EF < 2.5, increase EF by 0.05. This prevents the death spiral.
  - repetition += 1
  - nextReview = now + interval days

- **Easy (4):**
  - If in learning: immediately graduate (step=3, interval=1day)
  - If graduated: interval = Math.max(1, Math.round(interval * EF * 1.3))
  - EF += 0.15
  - repetition += 1
  - nextReview = now + interval days

Learning steps: step 1 = 1 minute, step 2 = 10 minutes, step 3 = graduated (1 day).

**EF floor enforcement:** ALWAYS `Math.max(1.3, newEF)` in ALL code paths.

**buildStudyQueue(allProgress, cardIds, { newLimit = 50, now = new Date() }):**
1. Get due cards: filter cardIds where progress exists AND nextReview <= now. Sort by nextReview ascending (most overdue first).
2. Get new cards: filter cardIds where NO progress exists. Take up to `newLimit`.
3. Return: [...dueCards, ...newCards] as array of cardIds.

**shouldReshow(cardId, againCounts):**
Returns true if cardId has been rated Again fewer than 3 times this session.
`againCounts` is a Map<cardId, number>.

**getInterleavingDistance(againCount):**
Returns number of cards to show between re-shows: 2 for first Again, 3 for second, 5 for third.

**isCardMastered(progress):**
Returns true if: totalReviews >= 3 AND lastRating >= 3 AND interval >= 1.

**isCardDue(progress, now):**
Returns true if nextReview is not null AND nextReview <= now.

**IMPORTANT:**
- NO React imports. Pure functions only.
- NO side effects. Every function returns new data.
- NO date mutation. Use date-fns addMinutes/addDays for nextReview calculation.
- Import date-fns: `import { addMinutes, addDays, isBefore, isEqual } from 'date-fns'`
- Dates stored as ISO strings in progress (JSON-safe).
