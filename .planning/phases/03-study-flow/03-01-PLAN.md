Create `src/hooks/useStudySession.js` exporting a single custom hook:

```js
export function useStudySession(deckId)
```

**Parameters:**
- `deckId` (string) — the deck to study, from route params

**Internal State (useRef/useState):**
- `queue` (string[]) — ordered card IDs to study (built once on mount)
- `currentIndex` (number) — position in queue
- `isFlipped` (boolean) — whether the card back is showing
- `isComplete` (boolean) — session is finished
- `againCounts` (Object) — cardId -> number of Again ratings this session (for re-show cap)
- `ratingsBreakdown` ({ again: 0, hard: 0, good: 0, easy: 0 }) — running totals
- `cardsCompleted` (number) — total cards rated (excluding re-shows that didn't advance)
- `sessionStarted` (useRef boolean) — prevents double StatsService.startSession

**Initialization (useEffect on mount):**
1. Get deck card IDs: `getCardsByDeck(deckId).map(c => c.id)`
2. Read `cardProgress` from `useProgressState()`
3. Read `settings.newCardsPerSession` from `useSettingsState()`
4. Build queue: `SrsService.buildStudyQueue(cardProgress, deckCardIds, { newLimit: settings.newCardsPerSession })`
5. Store `queue` = result.queue (array of card IDs)
6. Call `StatsService.startSession()` (guarded by sessionStarted ref)
7. If queue is empty, set `isComplete = true` immediately

**Returned API:**
```js
return {
  // Current state
  currentCard,    // card object from getCardById(queue[currentIndex]) or null
  isFlipped,      // boolean
  isComplete,     // boolean
  // Progress
  cardsCompleted, // number
  totalCards,     // queue.length
  // Actions
  flip,           // () => void — sets isFlipped = true
  rate,           // (rating: 1|2|3|4) => void — processes rating and advances
  // Session result (only meaningful when isComplete)
  sessionResult,  // { cardsReviewed, accuracy, duration, ratingsBreakdown } or null
}
```

**`flip()` function:**
- Sets `isFlipped = true`
- No-op if already flipped or isComplete

**`rate(rating)` function:**
This is the core logic. Steps:
1. Get current cardId from `queue[currentIndex]`
2. Get current progress: `cardProgress[cardId]` or `SrsService.createCardProgress(cardId)` if new
3. Compute new progress: `SrsService.reviewCard(progress, rating)`
4. Dispatch to ProgressContext: `dispatch({ type: 'REVIEW_CARD', payload: { cardId, progress: newProgress } })`
5. Track rating: increment `ratingsBreakdown[ratingName]`
6. Increment `cardsCompleted`
7. Handle Again re-show:
   - If rating === 1 (Again):
     - Increment `againCounts[cardId]`
     - If `SrsService.shouldReshow(cardId, againCounts)`:
       - Get distance: `SrsService.getInterleavingDistance(againCounts[cardId])`
       - Insert cardId into queue at position `currentIndex + 1 + distance` (clamped to queue.length)
8. Advance: `currentIndex++`
9. Reset flip: `isFlipped = false`
10. Check completion: if `currentIndex >= queue.length`:
    - Call `const result = StatsService.endSession(cardsCompleted, ratingsBreakdown)`
    - Set `sessionResult = { cardsReviewed: cardsCompleted, accuracy: result.accuracy, duration: result.duration, ratingsBreakdown }`
    - Set `isComplete = true`

**Cleanup (useEffect return):**
- On unmount, if session was started but not completed, call `StatsService.endSession(cardsCompleted, ratingsBreakdown)` to prevent data loss.

**Important implementation notes:**
- Use `useState` for reactive state (currentIndex, isFlipped, isComplete, sessionResult)
- Use `useRef` for mutable non-reactive state (queue array, againCounts, ratingsBreakdown, cardsCompleted, sessionStarted) — these change during rating but don't need to trigger re-renders on their own (the currentIndex change triggers the re-render)
- Import `getCardsByDeck, getCardById` from `../data/index.js`
- Import `SrsService, AGAIN` from `../services/SrsService.js`
- Import `StatsService` from `../services/StatsService.js`
- Import `useProgressState, useProgressDispatch` from `../contexts/ProgressContext.jsx`
- Import `useSettingsState` from `../contexts/SettingsContext.jsx`
- The queue is a mutable ref array — the Again re-show inserts into it via splice
- `cardsCompleted` should be a ref too, but expose its `.current` via the return object — or use a state if needed for reactivity. Since it's displayed in the UI during the session, use useState for cardsCompleted.
- Actually, reconsider: `cardsCompleted` needs to re-render the progress indicator, so use useState. But `ratingsBreakdown` and `againCounts` only need to be read at session end, so useRef is fine for those.
